# 缠论原文蒸馏

目标：把缠论原文、可复核的形式化规则、工程实现和测试案例分开管理，逐步构建可追溯、可测试的缠论分析工具。

## 项目原则

1. **原文优先**：规则必须能追溯到明确的原文出处；未核实的内容不得伪装成原文引用。
2. **分层记录**：区分原文摘录、形式化解释、工程约定和 AI 推断。
3. **显式标记状态**：
   - `UNVERIFIED`：尚未核对原文
   - `SOURCE_CHECKED`：已核对指定来源
   - `CROSS_CHECKED`：已与其他相关原文交叉核对
   - `TESTED`：已有测试案例验证实现行为
   - `DISPUTED`：存在歧义或不同解释
4. **不偷换概念**：任何为方便编程作出的约定，都要单独说明，不能直接说成缠论原文。
5. **可复现**：规则应配有输入、预期结果、边界情况和测试。

## 当前阶段

先建立包含关系与分型的候选规则及人工测试。当前文档中的公式是工程候选定义，除非明确标注来源并完成核对，否则不能视为已证实的原文规则。

## 目录

- `sources/source-index.md`：原文来源与核验记录
- `rules/01-inclusion.md`：K 线包含关系
- `rules/02-fractals.md`：顶分型与底分型
- `tests/01-manual-cases.md`：人工测试案例

## 后续路线

1. 建立可信的原文来源索引并记录版本、标题和段落位置。
2. 核对包含关系及分型的定义和边界条件。
3. 再实现笔、线段、中枢、背驰与买卖点。
4. 对每条规则建立单元测试，并保留争议案例。
5. 接入行情数据前，先明确复权、交易日、未收盘 K 线及数据缺失的处理约定。

## 风险声明

本项目用于研究与规则验证，不构成投资建议。任何程序输出都应经过数据和规则核验，不应直接作为交易指令。
