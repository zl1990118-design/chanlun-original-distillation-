# 规则 02：顶分型与底分型

状态：`UNVERIFIED`（工程候选，尚未完成原文核验）

## 输入前提

本规则假设输入已经按项目的 K 线包含关系规则完成标准化。若输入未标准化，分型结果可能不同。

## 候选三 K 线定义

设连续三根标准化 K 线为 A、B、C，中间一根为 B。

### 候选顶分型

同时满足：

- B.high >= A.high
- B.high >= C.high
- B.low >= A.low
- B.low >= C.low

### 候选底分型

同时满足：

- B.high <= A.high
- B.high <= C.high
- B.low <= A.low
- B.low <= C.low

这组条件是用于建立测试的宽松候选定义，并非已核实的最终缠论规则。

## 边界与冲突

- 相邻 K 线最高价或最低价相等时，是否成立需要按原文及一致的形式化口径核验。
- 若同一组 K 线同时满足顶、底候选条件，应记录为退化/平坦案例，不应未经定义就任意选一类。
- 需要明确分型的确认时点，避免在 C 尚未收盘时把信号当作已确认。
- 后续若对标准化 K 线进行回溯修订，应重新计算受影响的分型。

## 工程输出建议

每个分型结果至少包含：

- 类型：`TOP_CANDIDATE` 或 `BOTTOM_CANDIDATE`
- 中间 K 线的标准化索引
- 对应原始 K 线索引/时间范围
- 规则版本与核验状态
- 确认状态及产生信号的时间

## 测试要求

覆盖严格顶分型、严格底分型、普通非分型、相等高低点、平坦区间、未收盘 K 线等案例。具体输入见 `tests/01-manual-cases.md`。
